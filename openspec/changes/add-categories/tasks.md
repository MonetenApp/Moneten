## 3. Pending transactions count

- [x] 3.1 Write the test first in LedgerTests: with today 09.11.2026, a category with a booked -80,00 €, a pending -40,00 €, and a pending -5,00 € with `review != nil` in November 2026 has the sum -120,00 € for "Current month" in `Ledger.sidebarAmounts(today:)`, which replaced `Ledger.sum(ofCategory:in:)`. Verified by LedgerTests "The sum of a category for the current month counts a pending row and leaves out a pending row marked for review". With `isInSum(of:)` set back to `!isPending && currency == currency`, it fails with -80,00 €, and with `currency == currency` alone, it fails with -125,00 €.
- [x] 3.2 Count pending rows with `review == nil` in `Transaction.isInSum(of:)` in `Sources/Domain/Models.swift`, which #139 adds. `Ledger.sidebarAmounts(today:)` calls it for the sidebar. This is the same edit as task 3.2 of the change `add-charts`, done once. The status line of the category view counts pending rows already. The task for `review` in the change `add-account-refresh` leaves the marked ones out of its sum, and its number still counts them. Done by #160, which let `isInSum(of:)` call `countsInSums`. The test of task 3.1 proves it.
- [x] 3.3 Once the change `add-split-transactions` builds splits, count the parts and not the original in `Ledger.sidebarAmounts(today:)` and in the number and the sum of the status line. Write the tests first with the scenarios "Split transaction" of "Amount in the sidebar" and "Category view". Verified by SplitLedgerTests "A split row in the sidebar counts its parts in their categories, not the original" and "The category view counts the parts and not the original".
