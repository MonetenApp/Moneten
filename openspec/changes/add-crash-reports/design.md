## Ownership

[ADR 0002](../../../docs/decisions/0002-local-first-no-server.md) forbids telemetry. Domain accepts a plain crash diagnostic struct and builds a report without I/O. Only numeric versions, exception and signal numbers, known binary names, valid binary UUIDs, and offsets can enter its text. Unknown binary names become "Other". Binary UUIDs identify release artifacts, never a device, installation, or database.

App maps MXCrashDiagnostic to the struct. It reads only the crashed thread of the stack tree. Objective-C reasons, termination reasons, memory details, process identifiers, and other metadata never enter the report builder.

Storage uses AES-GCM and a dedicated random key protected by the existing Keychain implementation. This works before the database unlocks and needs no schema migration. A Debug or Perf run with its own data folder (`MONETEN_DATA_DIR`), such as a run of the debug harness, keeps the key in the file `CrashReport.key` of its data folder instead. A build without a team gets a new signature each time, and macOS asks for the login password when it reads a Keychain entry of an earlier build. Release builds and runs without the harness always use the Keychain. One encrypted state holds the newest payload end time or decided fallback time, the pending report, the launch start and versions, and the correlation context of a decided short report. A pending fallback stores its file date and the previous launch start together, so later launches preserve the correlation window. A first launch records its start without inferring a crash. Each later launch first checks files newer than the saved start and older than this launch, then saves the new start. A decision removes the diagnostic but retains its time. Completing a short-report decision advances that saved time and retains the fallback file date and previous launch start. A decision suppresses the same bounded-start window as a pending fallback, as well as broad payload intervals containing the decided file date. This also suppresses payloads from older decisions. A newer pending fallback can still receive its matching details. MetricKit exposes payload times, not individual crash times. Within the newest payload the last crash is kept.

App shows the sheet above the root view, including while the database is locked. A cut report stays after opening GitHub until Copy Report or Don't Report. A failed deletion leaves it available and shows an error. Opening a browser is an explicit action; submitting the issue remains the user's choice.

Domain constructs the GitHub URL with template bug-report.yml and fields version and macos. The report goes only into the form's expected field. The encoded URL stays below 8,000 characters. It truncates only between frame lines and appends a notice. The pasteboard always gets the full report.

Maintainers use scripts/symbolicate-crash.sh with the matching dSYMs. The script matches binary UUIDs and adds each offset to the Mach-O text segment address before calling atos. This change records dSYM retention in the open release tasks and does not implement uploading.

App lists only Moneten-*.ips and Moneten*.crash in the user's Library/Logs/DiagnosticReports directory and reads their modification dates. It never opens a system report. Storage makes the fallback decision from those names and dates and the saved launch state. The short report includes only saved versions, the newest matching date in UTC, and "No details were available." While a short report awaits a decision, a MetricKit payload replaces it when its start is at or after the whole minute of the saved previous launch start and no later than the file modification date plus 60 seconds. MetricKit gives payload times in whole minutes: a crash 17 seconds after a launch at 10:58:21 arrived as a payload from 10:58:00 to 10:58:00. A start strictly after the launch would reject every crash in the minute of its launch. The launch minute is open only when no earlier crash file, short report, payload, or decision falls in that minute; otherwise the minute can belong to the earlier crash, and the newer short report stays. An earlier crash file is any crash file dated before the file of the short report: ReportCrash can write the file of a crash after the next launch started. A decision raises the saved latest time to the date of its short report, so that time also stands for the decision when the crash file is gone. The payload end may precede the file date because ReportCrash can write the file after the crash. This match bypasses the newest-payload replay guard. Once details replace the fallback, the saved latest time suppresses a replay after a decision. Payloads expose intervals rather than individual crash times, so this bounded start-time match is the available correlation signal. No quit marker is used. MetricKit delivers only to a build signed with a team. For an ad hoc signed build, which every build without a team in `App/Local.xcconfig` is, metrickitd refuses the delivery, and only the short report appears. The crash of a bundle ID that macOS does not yet know as a MetricKit client also gets only the short report. The existing main-window dialog observer also observes pending crash reports.

Loading has four outcomes: no file, state read, permanently unreadable state, and access unavailable for now. Only a missing or invalid-length key, malformed encrypted box, authentication failure, or JSON decoding failure deletes the file. Any Keychain failure or unclassified error preserves the file and is rethrown. That launch offers no saved report; the next launch retries with the same baseline.
