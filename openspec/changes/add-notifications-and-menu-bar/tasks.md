# Tasks

One task per requirement of the spec. A task is checked only when a test or a check in the running app shows the behavior. The issue in brackets builds it.

## 1. Requirements

- [x] 1.1 One notification for a refresh with new transactions. Verified by NewTransactionsNoticeTests "New transactions in two accounts make one notice...", AutoRefreshTests "The run ends once, after the last of several accesses...", "New transactions of a run make one notification...", and "An automatic refresh of three accesses makes one notification...", and the debug app check of issue #40, which delivered one notification for each run (#40).
- [x] 1.2 Notify only about stored transactions. Verified by NewTransactionsNoticeTests "Only rows that are still stored and still new count" and AutoRefreshTests "An automatic refresh of three accesses...", whose second run delivers the same rows and makes no notification (#40).
- [x] 1.3 Notifications reveal no transaction details. Verified by NewTransactionsNoticeTests "One new transaction names its account and nothing of the transaction" and "While the app is locked the notice has the count and no account name" (#40).
- [ ] 1.4 Open the account from a notification. Built: a click brings the main window to the front with the first of the accounts in the order of the sidebar, after the unlock when the app is locked. The debug app check sent `noticeclick`, which hands the accounts of the delivered notification to the handler of a click, with the main window closed and Tagesgeld selected: the main window opened with Girokonto. Locked, the main window opened with the lock screen, and the unlock selected Girokonto. Open: a click on a real banner, which needs the permission of macOS that only a person can grant, and the dashboard comes with add-dashboard (#40).
- [x] 1.5 Remove notifications that are out of date. Verified by the debug app check: the notification about 6 new transactions in Girokonto and Tagesgeld stayed in the Notification Center after Tagesgeld was opened and went once Girokonto was opened, and three notifications about Girokonto went together when the user opened it (#40).
- [ ] 1.6 Sound on new transactions. Built, and AutoRefreshTests "New transactions of a run make one notification, with the sound only when the setting is on" and NewTransactionsNoticeTests "The sound follows the sum..." verify the choice. The debug app check ran while macOS denied the notification permission. With the banner off and the sound on, a run with a withdrawal made one call to NSSound for the negative sound, and play() returned true. With the banner on, the "notice" log named the positive sound of a run with a deposit, and the delivered notification carried a sound. With the sound off, the app made no call. That shows the call and the choice of the sound. Open: nobody listened to the sound, and the sound of a banner needs the permission, which only a person can grant (#40).
- [ ] 1.7 Respect Focus. Built for the banner, whose sound is part of the notification. Open: the sound without a banner ignores a Focus, see "Decided for Moneten" (#40).
- [ ] 1.8 Dock badge with the number of new transactions. Built. Open: macOS shows the badge only with the notification permission, which only a person can grant, so the badge was not seen (#40).
- [ ] 1.9 Ask for permission and explain a refusal. Built: the app asks when the user turns on the banner or the sound or when the first notification is due. The debug app check saw macOS show the request at the first notification, and with the permission denied, the "General" tab showed the note and the button to the System Settings. Open: the note was not seen to go after a later permission, which only a person can grant (#40).
- [ ] 1.10 Notification about new statements. Comes with add-bank-statements.
- [x] 1.11 Menu bar icon. Verified by the debug app check: `setting showMenuBarIcon on` and `off`, which write the default of the toggle, put the icon into the menu bar and took it out without a restart, and a screen capture of the menu bar showed it come and go (#40).
- [x] 1.12 Menu bar popover. Verified by the debug app check of issue #40: the popover lists the open accounts in the order of the sidebar with balance and count of new transactions, and marks the two accounts whose access waits for a TAN (#40). The row shows the balances of the sidebar row from `Ledger.balances(of:)`, which SeveralBalancesTests "The sidebar, the header, and the sum of the group show every balance..." covers. Verified by `menubarsnapshot` in light and dark: after the harness command `wallet`, the row "Reisekasse" showed 0,00 € and 35,00 US$ (#338). A long name with large balances and the mark of a failed refresh keeps every amount on one line and shortens the name (#359). Verified by `menubarsnapshot` in light and dark after `wallet` with a long name and `refreshfailed`: before, 12.345.678,00 € and 9.876.543,00 US$ wrapped onto two lines each; after, both stay on one line beside the mark and the name ends with an ellipsis.
- [x] 1.13 Actions in the popover. Verified by the debug app check with `menubar press`, which clicks a control of the open popover: with the main window closed, "Refresh All Accounts" refreshed all three accounts, the popover showed the progress line and a spinner in each row, and then the new balances; a click on the row Girokonto opened the main window with Girokonto selected; "Open Moneten" opened the main window. Offline, the popover said so and its refresh command did nothing (#40).
- [x] 1.14 Menu bar icon shows the state. Verified by the debug app check: the icon showed the marker for new transactions after a refresh, kept it while one of two accounts was still unseen, and lost it once both were seen; it showed the running refresh during a refresh, the warning while Tagesgeld had a failed refresh, and the plain icon while locked (#40).
- [x] 1.15 The popover respects the lock. Verified by the debug app check: locked, the popover showed only "Moneten is locked." and the button "Unlock...", no account, and the button opened the main window with the lock screen (#40).
- [x] 1.16 Keep working with the main window closed. Verified by the debug app check with `MONETEN_DEBUG_CLOCK_OFFSET` 7155 and `present on`: with the main window closed and the app unlocked, the automatic refresh ran 83 seconds later, stored 1 new transaction, and posted the notification "1 new transaction", and the menu bar icon kept showing the state. With "Lock when main window is closed" on, closing the main window locked the app, and in the next 150 seconds no refresh ran and no notification came (#40).
